# Cosmic Transcriber Web V1.2 Regression Audit Gate

Status: **MANDATORY / FAIL-CLOSED**

This gate exists to prevent V1.2 multi-format work from accidentally deleting or weakening behavior that was hardened in the certified V1.1.1 line.

V1.2 must remain `releaseReady:false` until this gate and the normal dependency-backed/platform release gates pass.

## 1. Controlling comparison

Compare the complete V1.2 candidate against the exact certified V1.1.1 source used for production, not against an earlier development candidate.

Classify every changed/deleted file and every deleted exported function/event handler into one of:

1. intentional V1.2 format-support change;
2. intentional test/release-infrastructure change;
3. documentation/version metadata change;
4. unrelated drift requiring explicit review;
5. unexplained deletion/change — **release blocker**.

No unexplained deletion may be waived by snapshot update alone.

## 2. BYOK/session security invariants

V1.2 must preserve all hardened V1.1.1 behavior for:

- Configure API key dialog;
- Test API key;
- Forget API key;
- plaintext key clearing on success, cancel, close and Escape;
- no plaintext API key persistence in browser storage;
- single-flight secure session creation;
- HttpOnly + Secure + SameSite cookie behavior;
- origin/subject/key-version AAD binding;
- Access principal validation;
- canonical Access team-domain validation;
- expiry handling and renewal reporting;
- no deployment-owner API-key fallback.

A source-diff safeguard must fail if the hardened handler block or equivalent behavior disappears.

## 3. Billing and checkpoint invariants

Preserve these V1.1.1 billing rules:

- no automatic retry after billing-ambiguous dispatch;
- checkpoint persisted before cancellation can lose completed work;
- completed-result validation failures after dispatch remain billing-ambiguous;
- unknown post-dispatch 4xx responses are not treated as definitely unbilled;
- prepared payload/chunk is rehashed before dispatch;
- checkpoint source fingerprint is validated;
- completed checkpoint reuse requires completed status and schema-valid result;
- explicit rerun semantics remain distinct from accidental duplicate dispatch.

V1.2-specific identity rule:

- MP3 checkpoint identity continues to bind MP3 paid-effective chunk controls;
- non-MP3 whole-file formats MUST NOT bind MP3-only chunk-size, max-chunk-duration or previous-chunk-context controls.

Required regression:

1. transcribe a WAV fixture once;
2. change every MP3-only control;
3. explicitly rerun the completed WAV;
4. verify exact checkpoint reuse;
5. verify upstream transcription request count remains **1**.

## 4. Multi-format client/server binding

Supported V1.2 formats:

- MP3
- FLAC
- MP4
- MPEG
- MPGA
- M4A
- OGG
- WAV
- WebM

Browser and Worker canonical format/MIME catalogs must agree exactly.

Before any paid dispatch, independently validate server-side agreement among:

- metadata `audioFormat`;
- incoming `Content-Type`;
- canonical server MIME;
- upstream multipart filename extension;
- upstream multipart MIME.

Any mismatch must fail before the OpenAI request.

Metadata V1 remains legacy MP3 compatibility only. Metadata V2 is required for direct-format identity/binding.

## 5. Container validation invariants

MP3 retains frame-aware validation/chunking.

All non-MP3 supported formats are whole-file uploads only and must not be arbitrary byte-split.

Application byte ceiling remains 24,000,000 bytes unless a separately reviewed change explicitly modifies it.

Oversized direct-format input must fail before paid dispatch.

Signature/container checks must remain bounded and fail closed.

For MP4/M4A ISO-BMFF validation:

- scan no more than first 64 KiB;
- inspect no more than 16 top-level boxes;
- support standard 32-bit and extended 64-bit box sizes;
- reject malformed/out-of-bounds box sizes;
- permit structurally valid leading boxes before `ftyp`;
- require structurally valid `ftyp` payload;
- reject arbitrary embedded `ftyp` substring matches.

## 6. Queue/UI invariants

Regression-test at minimum:

- start requires at least one eligible queue item;
- queue remains naturally sorted across additions;
- completed checkpoint presentation-only settings do not invalidate paid work;
- cancellation/resume state remains coherent;
- diarization controls retain model/language contract;
- TXT/Markdown output naming remains format-independent and deterministic;
- generated Markdown labels remain escaped;
- unsupported extension/MIME conflict surfaces locally without paid dispatch.

## 7. Deployment-helper invariants

Machine-readable Wrangler child invocations must strip inherited diagnostics/structured-output environment variables that can corrupt stdout parsing, including at least:

- `WRANGLER_LOG`
- `WRANGLER_LOG_PATH`
- `WRANGLER_LOG_SANITIZE`
- `WRANGLER_OUTPUT_FILE_PATH`
- `WRANGLER_OUTPUT_FILE_DIRECTORY`
- `FORCE_COLOR`

Cloudflare authentication/account environment variables must remain available.

D1 list parsing must:

- bound captured stdout;
- require an actual JSON array;
- fail closed on malformed/non-array output;
- tolerate only explicitly reviewed bounded surrounding CLI noise.

Regression must cover the historical production preparation failure where structured Wrangler output caused `d1 list` parsing to report that it did not return a JSON array.

## 8. Release-state invariants

Until all mandatory release gates pass:

- package/app version may identify 1.2.0;
- release manifest MUST say `releaseReady:false`;
- final/certified ZIP MUST NOT be emitted;
- staging candidate may be produced only after local/dependency-backed certification gates pass;
- production V1.1.1 remains untouched.

Do not change `releaseReady` to true merely because dependency-free/static tests pass.

## 9. Required executable evidence

Record exact counts, not prose-only claims, for every executed gate.

Dependency-free/local:

- syntax/type-shape/linkage validation;
- functional tests;
- static/security/release safeguards;
- mutation suite;
- secret scan;
- version consistency.

Dependency-backed/runtime:

- `npm ci` under reviewed Node/npm versions;
- Worker Vitest;
- whole-Worker integration tests;
- Playwright Chromium/Firefox/WebKit;
- installed Chrome;
- installed Edge;
- macOS WebKit/real Safari gate where required by release policy;
- Windows release certification;
- build inspection;
- source packaging;
- fresh ZIP extraction;
- `npm ci` and complete re-verification from extracted ZIP.

A gate not executed is **NOT RUN**, never PASS.

## 10. Real-format fixtures

Maintain decoder-readable fixtures for every non-MP3 format and verify both:

1. application signature/container acceptance;
2. external decoder/probe readability (`ffprobe` or equivalent release-environment check).

Fixture extension, MIME and actual container must agree.

## 11. Staging acceptance before production

After a locally certified staging candidate exists, test one short sample per format and minimize repeated paid tests.

Mandatory staging checks include:

- all nine supported formats;
- explicit FLAC and OGG live transcription;
- extension/MIME mismatch rejection with zero paid requests;
- malformed-signature rejection with zero paid requests;
- oversize-direct-container rejection with zero paid requests;
- completed WAV checkpoint reuse after MP3-only setting changes;
- cancellation/resume;
- billing-ambiguous confirmation behavior;
- diarization;
- Access/admin/account enforcement.

Production remains blocked until staging acceptance is recorded.

## 12. Audit output

Each completed regression-audit run must produce:

- exact V1.1.1 controlling source identity/hash;
- exact V1.2 candidate identity/hash;
- file-level changed/deleted/added inventory;
- list of every unexplained deletion (must be empty to pass);
- invariant checklist result;
- exact test counts;
- exact NOT-RUN gates and reason;
- release-state assertion (`releaseReady:false` until certification);
- next blocker/action.

The audit is PASS only if no unexplained deletion or weakened invariant remains.
