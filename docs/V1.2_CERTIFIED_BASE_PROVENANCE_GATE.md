# V1.2 Certified-Base Provenance Gate

Status: MANDATORY / FAIL CLOSED

This gate controls the V1.1.1 source used as the regression-audit baseline for Cosmic Transcriber Web V1.2.0.

## Why this gate exists

A branch name is not certification evidence.

The repository branch named `ci/1.1.1` must **not** be treated as the certified V1.1.1 application source merely because of its name. Its repository root is a CI carrier rather than a materialized application tree, and its existing `.ci/certification-marker.txt` identifies a hosted **1.0.12** source snapshot. Historical carrier files may also include builders or archives for several versions.

Therefore the V1.2 regression audit must never use `ci/1.1.1` (or any other branch/worktree) directly as the certified baseline unless the exact materialized V1.1.1 application artifact has first been independently proven.

## Required baseline evidence

Before `tools/v12-regression-audit.mjs --base ...` may be counted as valid V1.2 evidence, the baseline directory must be materialized from the exact certified V1.1.1 artifact and must satisfy **all** of the following:

1. `package.json` identifies version `1.1.1`.
2. `RELEASE_MANIFEST.json` identifies product `Cosmic Transcriber Web`, version `1.1.1`, and `releaseReady:true`.
3. The source archive bytes are bound to the exact V1.1.1 certification evidence, including the certified ZIP/source-archive SHA-256 and, where available, the successful certification run/artifact identity.
4. Materialization occurs into a clean directory; no files from another version, prior extraction, dependency install, build output, or evidence directory may be mixed into the baseline.
5. The clean materialized baseline is hashed with the same deterministic whole-tree algorithm used by `v12-regression-audit.mjs`.
6. That independently verified materialized-tree SHA-256 is supplied to the audit with `--expected-base-tree-sha256`.
7. The auditor independently recomputes the baseline tree SHA-256 and requires an exact match before it inspects the V1.2 candidate or accepts any comparison evidence.
8. Any mismatch between certification evidence and materialized bytes blocks the V1.2 audit. Do not substitute a similarly named branch, archive, builder output, or later production copy.

The certified archive SHA-256 and the deterministic **materialized tree SHA-256 are different evidence values**. Do not substitute one for the other. The archive hash proves the recovered package bytes; the tree hash binds the clean extracted source snapshot used in the comparison.

## Executable binding

Regression-audit schema v4 requires the expected materialized V1.1.1 tree hash on every invocation:

```bash
node tools/v12-regression-audit.mjs \
  --base /path/to/clean-certified-v1.1.1 \
  --expected-base-tree-sha256 <independently-verified-64-lowercase-hex-tree-sha256> \
  --candidate /path/to/CosmicTranscriberWeb-1.2.0-dev \
  --json evidence/v12-regression-audit.json
```

There is intentionally **no built-in default V1.1.1 tree hash** while the exact certified artifact is unavailable. Inventing or guessing a hash would defeat this gate. Recovery of the exact artifact and its certification evidence remains a blocker until the expected tree hash can be derived and independently recorded.

A schema-v4 PASS records:

- `base.treeSha256` — independently recomputed from the supplied baseline directory;
- `base.expectedTreeSha256` — the externally supplied expected tree identity;
- `base.provenanceVerified:true` — set only after those two hashes match.

The downstream critical-change reviewer rejects audits without this binding.

## Explicitly unsafe shortcuts

The following are NOT sufficient proof of the V1.1.1 baseline:

- branch name `ci/1.1.1`;
- `package.json` version alone;
- `RELEASE_MANIFEST.json` values alone;
- a directory manually renamed to `1.1.1`;
- a tree hash calculated from an unverified directory and immediately supplied back as its own expected value;
- a historical `.ci` builder script;
- an archive whose filename merely resembles a V1.1.x version;
- production deployment state without exact source-artifact provenance;
- a prior chat statement without recoverable hash/run evidence.

## Current repository observation

At the time this gate was added, `ci/1.1.1` contains a CI carrier root (`.ci`, `.github`, README and a compressed CI-source archive), not the materialized V1.1.1 application tree. Its `.ci/certification-marker.txt` states:

`Cosmic Transcriber Web 1.0.12 hosted certification trigger.`

and records a 1.0.12 source snapshot SHA-256.

Accordingly, that branch is **not approved** as the V1.2 regression baseline.

## Required execution order once the V1.2 application tree is available

1. Recover the exact certified V1.1.1 artifact and its certification hash/run evidence.
2. Verify the certified archive hash before extraction.
3. Extract/materialize into a clean baseline directory.
4. Verify V1.1.1 package/manifest identity.
5. Compute and independently record the deterministic materialized whole-tree SHA-256 from that verified extraction.
6. Run the schema-v4 V1.1.1 -> V1.2 regression audit with that exact hash supplied through `--expected-base-tree-sha256`.
7. Run the schema-v4 exact-hash critical-change review.
8. Run product functional/static/mutation suites.
9. Run the exact Node 26.7.0 / npm 12.0.2 Worker, integration, browser and platform certification matrix.
10. Create a staging candidate only after those gates pass.

## Release-state rule

This gate does not certify V1.2. It only prevents a false comparison baseline. V1.2 remains `releaseReady:false` until every required release gate and staging acceptance gate passes.
