# Browser release policy — 2026-10-11-target-platforms-v1

This prospective policy tests the shipped browser targets on their actual operating systems. It does not certify the previously failing Windows Playwright WebKit run, claim the runtime defect is fixed, or change application behavior. Every required test below must execute and pass on the exact reviewed source, dependency graph and fixtures. Unknown host platforms fail closed.

For the 1.2.0 regression release, the owner-approved [22 October Safari exception](RELEASE_EXCEPTION_2026-10-22.md) permits only the exact verified SafariDriver 26.6.2 native-file failure to be recorded as **WAIVED**. The test still runs and retains FAIL; genuine Mac Safari is not validated. All other platform, security, billing, provenance and live acceptance requirements below remain mandatory. A release-browser eligibility result under that exception is not full Safari or production certification.

| Host | Required browser coverage |
| --- | --- |
| Windows | Complete shared suite in Chromium, Firefox, installed Chrome and installed Edge; ten-repeat Firefox secure-key stress; exact private toolchain; complete fresh-ZIP release verification using .NET extraction and original archive timestamps |
| Linux | Complete shared suite in Chromium, Firefox, WebKit and mobile Safari emulation; Worker and integration suites |
| macOS 26 | Complete shared suite in WebKit, mobile Safari emulation and installed Chrome; actual SafariDriver native-file and mocked workflow acceptance, from the unchanged Windows staging ZIP |

The shared suite includes native disk selection of MP3, FLAC, MP4, MPEG, MPGA, M4A, OGG, WAV and WebM, plus the exact Unicode MP3 fixture. Each case verifies native full and sliced reads against source SHA-256, unchanged source timestamps/bytes, and successful application preparation with the fixture's expected duration. Selecting a file or seeing Ready alone does not prove correct duration probing: the application has a 0.001-second fallback, which these fixtures must not satisfy. Duplicate-content fixtures are tested individually.

Actual SafariDriver adds native disk-backed File reads, meaningful media/app preparation duration, mocked dispatch identities/bytes, checkpoint/cancel/retry safeguards and transcript download payload checks. A payload check is not an operating-system download-completion claim. Genuine Safari manual/live acceptance remains separate. Mobile WebKit is emulation, not certification of an actual iOS device.

The macOS job verifies the Windows ZIP hash before native extraction, compares every extracted byte and timestamp with that ZIP, and runs from that extracted source. Windows fresh-package verification checks archive integrity before using .NET's actual extractor. Neither path alters file timestamps, rewrites MIME hints, replaces native inputs with in-memory File objects or substitutes different fixtures to avoid a runtime failure. Fixture generation and any dependency refresh invalidate prior receipts for changed bytes.

The prior inherited matrix also required Windows Playwright WebKit/mobile WebKit. A plain native File/Blob reproduction failed outside the application with Playwright 1.64.0/WebKit 2370 (36/99 reads) and an isolated 1.65.0-alpha-2026-10-10/WebKit 2374 (41/99). These historical failures remain failures. Windows WebKit is retained as a separately runnable runtime diagnostic through `test:e2e:core`; it is no longer the Windows browser certification target under this revision. Its test cases remain mandatory on Linux and macOS. The preview runtime is not a certified dependency replacement.

This change is based on the documented primary product targets, Windows Chrome/Edge and macOS Safari/Chrome, and transfers Safari-sensitive native-file proof to actual macOS Safari while adding coverage previously missing there. Playwright documents its WebKit as a patched upstream build rather than branded Safari, with platform differences; this is not a claim that Windows is unsupported by Playwright. See [Playwright browser documentation](https://playwright.dev/docs/browsers#webkit) and [Apple Safari WebDriver documentation](https://developer.apple.com/documentation/webkit/testing-with-webdriver-in-safari).

Security, billing, dependency, audit, mutation, Worker/integration, packaging, provenance and live staging/production gates are unchanged. CI uses one worker and zero automatic retries. The final aggregator requires every Linux, Windows and macOS job to succeed; missing, failed, cancelled or skipped gates do not pass. CI publishes only staging candidates with `releaseReady:false`; this policy does not authorize a release-ready flag change or deployment. Preserve exact source/lock/archive hashes, OS/browser versions, logs and failed-run evidence with the certification receipts. Historical local/remote passes are not evidence that this revised matrix has passed.
